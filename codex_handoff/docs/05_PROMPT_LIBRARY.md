# Codex 提示词库

## 只读仓库导航

```text
只阅读，不修改文件，也不要运行会改变环境的命令。

目标：定位 [具体目标] 的完整调用链。
输出格式：
1. 文件路径；
2. 函数/类/target 名；
3. 上游调用者；
4. 下游调用；
5. 关键输入输出；
6. 尚不确定的地方和验证方法。

只给出有代码证据的结论。不要扫描无关目录。
```

## 首个编译错误

```text
先不要修改代码。

这是我实际执行的命令：
[命令]

这是构建日志：
[日志路径]

请：
1. 复现或读取日志；
2. 找到第一个真实 error；
3. 区分根因和级联报错；
4. 给出最多三个候选根因并按概率排序；
5. 提供只读检查命令；
6. 等我确认后再做最小修改。

不要通过关闭功能、忽略警告或修改 third_party 来绕过问题。
```

## 小修改

```text
目标：[一个可测的小目标]

限制：
- 最多修改 [1-3] 个源文件；
- 不重构无关代码；
- 不修改 third_party；
- 不改变默认行为；
- 先给出计划和验证方法，等我确认后再编辑。

完成后：
- 运行最窄的相关测试；
- 汇总每个文件的变化；
- 说明未测试路径；
- 给我三个理解检查问题。
```

## 性能测量

```text
请审查这段 benchmark 的正确性，而不是只看它能不能运行。

重点检查：
- 是否 warm-up；
- timing boundary；
- CPU/GPU 同步；
- 是否包含数据传输；
- 是否重复测量；
- 是否报告 mean/std/p50/p95/p99；
- 是否有日志/计时本身带来的开销；
- 是否固定输入、seed 和环境。

先列问题，不直接重写。
```

## 实验设计

```text
请把下面的想法转成可证伪的实验计划：

研究问题：
[问题]

请输出：
- 假设；
- 自变量、因变量、控制变量；
- baseline；
- 数据/任务；
- 指标；
- 重复次数；
- 消融；
- 失败判据；
- 可能的混杂因素；
- 最小可行实验；
- 在 8 GB RTX 4060 上的资源约束。

不要夸大创新性。
```

## 代码审查

```text
请作为严格 reviewer 审查当前 git diff。

优先级：
1. correctness；
2. undefined behavior / ownership / thread safety；
3. CUDA synchronization；
4. error handling；
5. regression；
6. benchmark validity；
7. maintainability。

按严重程度输出，必须引用文件和行。没有证据的猜测要标为假设。
不要直接修复，先报告。
```
