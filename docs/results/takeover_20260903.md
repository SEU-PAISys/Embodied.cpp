## 1. TurboVLA: confirmed full-length text-mask defect

The C++ BERT mask began entirely closed. A later fallback restored diagonal
self-attention for BERT, but the text enhancer had already copied the incomplete
mask. When `[SEP]` occupied position 20 in the 21-token sequence, real-token rows
of the enhancer remained entirely masked. The reference implementation starts
from an identity matrix before opening sub-sentence blocks.

Two failing spatial instructions both tokenize to exactly 21 tokens, **including
CLS and SEP**; they are not truncated. A real-weight synthetic probe returned
finite actions, but the two different full-length instructions produced identical
first actions. Absence of NaN was therefore insufficient to validate this path.

Fix: initialize the BERT diagonal before deriving the enhancer mask; remove the
late BERT-only fallback. The regression compiles the actual production mask block
and checks SEP positions 10, 13, 18 and 20. Before the fix it failed with
`mask mismatch sep=20 q=1 k=1`; after the fix it passes.

## 3. Handoff figures that must not be promoted unchanged

- XR0's claimed normalized latency used `inference=42.53 ms`, whereas the same
  BF16 log has `total=97.02 ms` and `vision=16.34 ms`. The Python script times a
  synchronized model call on preprocessed GPU inputs. These boundaries are not
  equivalent; replacing one number with runtime total alone does not prove parity.
- The old C++ memory script sums processes across **all GPUs**, while Python uses
  `torch.cuda.max_memory_allocated()`. These cannot form a valid memory ratio.
- The server's TurboVLA checkpoint has SHA256
  `d031ad7be05a2f5d04afb3194ed26b0cb46083685edee7a5e145078a37d26bab`, versus local
